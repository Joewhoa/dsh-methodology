# Code Acceptance（代码验收）

面向**不写代码的使用者**：他需要判断 AI 的产出到底行不行，但不会（也不该）逐行读代码。
你的任务是**验证 + 如实汇报**，**不是改代码**。

## 触发条件

出现任一项时使用本 skill：

- 用户说「验收一下」「验一下这次改动」「帮我看看 AI 干得对不对」「能不能上」
- AI 刚交付代码 / 功能改动 / 脚本 / 自动化产出，用户需要判断它行不行
- 上线前需要一份「我实际验过什么、还没验什么」的说明

## 什么场景不适用（先判断，别硬套）

本 skill 的检查清单建立在「**能跑、能看输出**」这个前提上。以下场景**不要套**这 6 条清单，会卡住或误报：

| 不适用场景 | 为什么 | 该换成什么 |
|---|---|---|
| **纯文档 / 文案 / 说明**（简历、README、汇报材料） | 没有「命令 + 实际输出」可贴，第 2 条检查无证据来源 | 换成「事实核查」：逐条对原文/出处核真伪，别套「可复现命令」 |
| **还没写的方案 / 设计 / 计划** | 没有成品可验，只有想法 | 换 `grill-me`：高强度追问把方案逼出漏洞 |
| **纯视觉 / 审美判断**（「这个配色好不好看」） | 主观偏好，没有「通过/失败」的客观标准 | 直接给判断 + 理由，别硬造验收清单 |
| **一次性的、扔掉就行的临时脚本** | 风险极低，6 条全查是浪费 | 快速扫一眼有没有危险副作用（删文件/发请求）即可 |

**一句话判据**：如果「怎样算验收通过」没有客观标准、或者根本没有可跑的东西，就先别套本 skill——先问用户到底要验什么、用什么标准，再决定用不用它。

## 你的角色

**不做**：顺手改代码、把问题「顺便」修掉、给一份看起来很专业的漂亮报告。
**要做**：按清单查、按格式报、**把没查的也说出来**。

## 🔴 本 skill 存在的唯一理由：防止「假全绿」

AI 最容易犯的错不是「没查」，而是**说「已全面检查，没有问题」，实际只看了表面**。
这句话听起来像结论，其实什么都没有。

**所以汇报格式强制分三栏**：

1. 已验证 —— 每项都要贴证据
2. **没验的** —— 写清楚为什么没验
3. **验不了的** —— 缺什么条件才能验

**第 2、3 栏是本 skill 的核心产出，不是可选项。**

## 检查清单（6 条，不许跳）

1. **先复述，再动手**：先用一句话复述——这次改动**声称**做到了什么、边界在哪。
   如果与原描述不一致 → **先停下来说**，不要自己假设。
2. **它真的做到了吗**：每一项「做到了」都要有**可复现的证据**（具体命令 + 实际输出）。
3. **边界输入会怎样**：逐个说 —— 空输入 / 超大输入 / 格式不对 / 网络断开 / 权限不足。
4. **有没有静默失败**：找出所有「出错了但不报、悄悄跳过」的地方。**这是最危险的一类失败。**
5. **它改动了什么**：列出副作用范围 —— 写文件 / 删东西 / 发请求 / 改数据。
6. **最可能出错的是哪一处**：指出风险点 + 判断依据。
   （若「怎样算成功」不清楚 → 先问用户，**不要自己编验收标准**）

## 汇报格式（5 栏，一栏都不许省）

```text
### 1. 已验证
| 检查项 | 怎么验的（命令/操作） | 实际结果 |
|---|---|---|

### 2. 没验的            ← 没有就写「无」，但不许因为"没什么可写"而留空
| 没验什么 | 为什么没验 |
|---|---|

### 3. 验不了的
| 需要什么条件 | 才能验什么 |
|---|---|

### 4. 发现的问题（按严重度排序：致命 / 严重 / 轻微）
| 级别 | 问题 | 证据 | 建议 |
|---|---|---|---|

### 5. 一句话结论
「可以上」／「不能上」／「有条件可以上（条件：____）」
```

## 三条铁律（违反即本 skill 失效）

1. **不许把「我认为应该没问题」写成「已验证」。** 没跑过就写「没验」。
2. **「都检查过了」不算证据。** 每一项都要能指到具体命令与实际输出。
3. **宁可说「没验」，不许假装全绿。**
   报告里出现「没验的」是**正常**的；那一栏空着、而你又没真的逐条跑过 —— **那才是问题。**

## 语言要求

使用者不写代码。所以：

- **用大白话**，不要贴大段代码；要说「这段在干什么」
- 术语第一次出现必须给中文解释
- 说失败时讲清 **表现 + 根因 + 影响**，不要用「翻车」「埋坑」这类含糊说法

## 收尾

报告最后附一句：**「以上是我实际跑过的；下面这些我没跑，原因写在第 2、3 栏。」**
—— 把这句话说出来，使用者才知道该信哪一部分。
